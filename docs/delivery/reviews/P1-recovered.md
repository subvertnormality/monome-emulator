## What works

- `patches/norns/0005-native-session-hooks.patch` lines 85–89: the ack is a custom event posted *after* the input event on matron's own FIFO queue (`event_post(ev); ... event_post(event_custom_new(&ack_ops,...))`), so `status='applied'` genuinely means the native Lua callback has run, not merely enqueued. Case 7 in 0009 keeps that ordering because `dev_midi_emu_receive` posts its parsed events synchronously before the ack.
- `src/runtime/native.py:168-173`: a failing MIDI capture contract still writes the offending emission (`self.events.write(json.dumps(record)+'\n')`) before poisoning the session, and `Capture.accept` (`src/devices/midi/__init__.py:59-61`) fails closed on sequence gaps, backwards source time and the event limit. `tests/midi_native.py:86-88` and `overflow()` exercise these against real sessions.
- D15 conversion is correct against the pinned sources: `device_monome.h:20` stores `uint8_t data[4][64]`, `dev_monome_grid_set_led(..., int8_t val, ...)` (device_monome.c:137) wraps −4→252 and 260→4, and patch 0010's `md->data[q][...] & 15` reproduces the mext low-nibble pack. The fixture `native-grid-level-conversion.json` pins literal 12/15/4/0/15, authored independently of emulator output.
- `tests/mosaic_slice.py:113-115`: `load()` deliberately alters step 2 (`self.tap(2,1)`) before invoking the file dialog, so a Load that silently keeps the autosave-loaded state cannot produce the expected `[60,62,67,65]` table.
- `tests/mosaic_slice.py:79-83`: the live-edit gate requires *every* captured note after the edit to match the phase-rotated edited sequence; it cannot pass by waiting several cycles and ignoring a late edit.
- `tests/mosaic_slice.py:48-54`: the native `native-events.jsonl` input trace is compared to the workflow recipe (`assert normalized(native)==normalized(self.recipe)`), so a browser run that drops or duplicates a key/grid event fails even if MIDI happened to match.
- `fixtures/probes/clock-cancel-race/clock-cancel-race.lua:16-17`: the probe asserts `pcall(clock.resume,99999999)` still errors, so patch 0011's guard cannot silently swallow arbitrary unknown IDs; the unpatched baseline manifest `artifacts/runs/0c46826f.../manifest.json` retains the real `clock.lua:62: bad argument #1 to 'resume'` failure.
- `src/runtime/native.py:95-100`: required JSON seeds are parsed before any service launches, so Mosaic's permissive config loader cannot turn a malformed device file into a silently different musical result (`tests/midi_native.py:130-145` confirms with named `seed_json`/`seed_missing` codes).
- `src/automation/evidence.py:47-49,89-94`: fixture-only manifests cannot claim E/B tiers and a package without two distinct native session IDs is rejected (`tests/contracts/test_packages.py`).

## What doesn't work

- [MINOR] `docs/architecture/midi-contract.md:9-11` says "Native input uses the pinned upstream parser", but patch 0009 (`device_midi.c:283-291` in the build) changes that parser only in the emulator profile: `if (emu_enabled()) { ... continue; /* realtime does not consume partial/running status */ }`. Pinned upstream falls through to `midi_input_msg_start(state, 0xF8)`, which discards the partial message; `[144,60,248,100,61,0]` becomes `[248]`, `[144,100,61]` on hardware but `[248]`,`[144,60,100]`,`[144,61,0]` here (asserted at `tests/midi_native.py:60`). The emulator is therefore more permissive than a real norns for interleaved-realtime input. It is disclosed in `patches/norns/README.md`, but the contract sentence is false as written and a Mosaic MIDI-clock/recording workflow can pass here and fail on hardware. Either restore pinned behaviour in the emulator path or state the divergence as an explicit capability, not "pinned upstream".
- [MINOR] `src/automation/server.py:162-166`: on `POST /stop`, `app.backend.close()` can raise `cleanup_failed` (`native.py:302-303`). The `except ContractError` at line 168 returns 400 and never reaches `self.server.shutdown`, so `stopped.json` is never written and the session server process stays alive with its HTTP port. `session.stop()` raises, `Client.finish()` propagates, and nothing calls `/stop` again. Symptom: every failed native shutdown leaks one Python server process until a manual second `emu stop`.
- [MINOR] Over-engineering / dead tooling in the digest-bearing tree: `scripts/patch_clock_cancel_race.py` hardcodes `.runtime/builds/2a499068a35ca198/norns` (the current build is `da993410f493edec`, so it cannot run), `scripts/prepare_native_patch.py` edits the shared `.runtime/deps/norns` fetch cache in place, and `probes/c00/emu_bridge.c` is a stale duplicate of the file now carried by patch 0004. All sit under `scripts/`/`probes/`, which `source_identity()` hashes (`identity.py:165`), so touching them invalidates every evidence package while contributing nothing to the runtime. Remove them; the patches and `patches/norns/README.md` are the record.

## Risks

- [MINOR] `tests/mosaic_slice.py:85,125`: `assert self.snapshot()['midi_capture']['outstanding']==[]` runs immediately after `self.tap(1,8)` with only the 60 ms sleep inside `tap`. Mosaic drains pending note-offs through its clock, not synchronously in the grid handler. Under the load that already produced R09 this assertion will fail intermittently and be indistinguishable from an R08-style genuine stuck note.
- [MINOR] Patch 0011 removes a failure that is reproducible on real hardware: the C scheduler cannot retract an already-posted resume event on a norns either, so Mosaic's stop/reload path can hit `clock.lua:62` on the device. The emulator now hides that from a Mosaic developer. `patches/norns/README.md` says "Remove when the official runtime handles this cancellation race itself" but no upstream check is recorded; if upstream main has no guard, this needs to be filed upstream and listed as a known emulator/hardware divergence, not left implicit.
- [MINOR] `src/runtime/native.py:243-246`: a scheduled MIDI input sleeps up to 2 s inside `query()` while `server.py:141` holds `app.lock`, so every snapshot, heartbeat and browser poll stalls for that interval. Browser client leases expire at 2.5 s (`client_timeout`), leaving 0.5 s of margin before the watchdog releases held inputs mid-workflow.

## Gaps

- [MAJOR] No screen/frame content oracle exists for the M1 slice or A01. `docs/delivery/PLAN.md` C06 step 2 requires "Assert expected grid/screen state ... Await named stable frames after splash/dirty refresh", and the A01 oracle is "Ready state, frame/LED layout". `fixtures/scenarios/mosaic-boot.json` asserts only `ready`, `script` and `enabled_mods`; `tests/mosaic_slice.py` asserts one LED (`grid[16]==15`) and MIDI, and the browser phase only checks canvas == native framebuffer (renderer consistency, not expected content). A Mosaic whose page rendering is blank but whose sequencer works would pass M1. At minimum assert a named stable frame's independent property (e.g. text extents/pixel rows from the pinned page layout) after boot and after the edit.
- [MAJOR] Evidence is stale/incomplete relative to HEAD, as the author acknowledges (`C06.md`: "P1 and final source/evidence digests remain pending"). Concretely: all four `artifacts/c06/*/manifest.json` carry `revision 52ba51e` (the parent commit); the cited API package `46570af5` and the clock-race manifest `e827d694` carry digest `2ac2c01f…` while the cited browser package `0c81a46a` and the unmentioned newer API package `b9902499` carry `4450ec0c…`; `state.json` still names `46570af5` as the passing API package; there is no `C06-evidence.json`. `verify-evidence` against the current tree will report `stale_source` for at least one of the manifests C06.md cites. Rerun API, browser, `native-clock-cancel-race` and the contracts suite on the committed tree, record their paths/digests in `C06-evidence.json`, and reconcile `state.json`.
- [MINOR] The browser lane depends on absolute paths into a personal tool cache (`tests/browser_client.py:103`, `tests/browser_driver.cjs:120`, `tests/browser_package.ps1:329-330`). ## Improvements

- [MINOR] `server.py:162-166`: wrap `app.backend.close()` so that a `cleanup_failed` error is placed in the 400 response *and* `stopped.json`/shutdown still happen; cost is three lines and removes the orphaned-server failure mode above.
