# A02 — softcut services and explicit file-I/O failures

2026-09-08; audio-monitor after tranche-1 merge `f301e76`. This is implementation
and scoped acceptance evidence, pending the broader-tranche admission review.
Runtime remains pinned official norns with the admitted experimental candidate.
No upstream softcut/DSP or cheat codes source was changed.

The generic services fixture proves actual stereo JACK playback, independent
voice rate, input amplitude polls and channel separation, return to silence,
phase/position/render callbacks, callback stop/restart and output silence.
The rendered 16-step source is compared with independently generated samples.
The observed native silence must fail the same input-signal oracle.

The asymmetric sequence fixture verifies actual forward/reverse tone order,
half/double playback rate and loop wrapping. Forward audio must fail the reverse
oracle. An actual 24-bit WAV saved by softcut is compared sample-for-sample with
the independently generated 16-bit input (tolerance 1e-6), then reloaded into the
other buffer and observed on the other audio output channel. Basic live record,
input cancellation and isolated capture cleanup remain covered by A01; A03
must still exercise cheat codes' own application workflows.

## Runtime change

Pinned `crone/src/BufDiskWorker.cpp` logs failed reads/writes but stays alive.
The old automation path ignored those records and incorrectly remained healthy
after a missing sample. `NativeBackend.check_processes` now incrementally reads
complete crone log lines and propagates its explicit missing/empty-file,
channel-format, seek, open and aborted-write messages as sticky `audio_io_error`.
The crone log path and original diagnostic are retained. This does not claim to
catch failures upstream itself does not report. No SC or C++ patch was needed.
