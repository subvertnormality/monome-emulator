## Delivered behavior

Optional official Maiden2e64f7d is separately built and licensed GPL-3.0, with
checksum-pinned private Go/Node/Yarn tools and a pinned BSD-3-Clause WebSocket
dependency. The launcher verifies binary, web assets and explicit patch set.
Its Go service listens on an owned private Unix socket; authenticated HTTP and
origin/token-checked WebSocket relays connect the existing browser session to
actual matron/sclang stdin and output. sclang uses its supported emacs input mode.
No community runtime fork, alternate framebuffer or separate device path.

The official editor navigates the existing linked code tree, saves external
files, runs scripts and supports both REPLs. Restart stops only its owned native
services and Maiden relay, then launches a fresh session/token with the same
marked dataset and launcher configuration. A successful handoff is recorded.
SC failures remain sticky until that explicit restart; host service operations
are rejected. Normal controls offer an editor link; editor offers controls and
the owned restart action. Two sessions have independent cookies, processes and
data. Sharing an explicitly selected code root intentionally shares source edits.

Dataset markers identify the mapping independently of session ID. A held flock
prevents concurrent writers. Fresh launch remains the default; explicit reopen
rejects unmarked data, different mappings, linked startup files and reseeding.
Cleanup releases ownership. No existing user project was overwritten by tests.

## Limits and remaining admission work

This tests the actual norns/JACK/SC engine and capture boundaries, plus Windows
Chromium editor/control behavior. H01 separately covers WSLg/Windows desktop
output. Maiden is not audio transport. No browser latency, arbitrary engine,
physical peripheral, macOS, Apple Silicon or Docker claim is added here.
Original click/dropout limitations from H01 remain. An engine allocation error
can require restart; the patch does not promise recovery inside arbitrary engines.

Earlier builds needed explicit recovery after a Yarn timeout/interrupted linking.
Review found the finalization command too weak, so it was removed. Fresh complete
buildsmaiden-03 andmaiden-04 passed. The latter includes all five patches, records
source files, and rejects source/patch changes during build. No stale output can
be admitted through the removed recovery shortcut.
The launcher accepts a separately identified component; it does not install or
update scripts through the network automatically. Unsaved editor changes are
lost on restart; restart loads the original launcher entry.
