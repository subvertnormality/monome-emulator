# H03 browser audio reliability and measured latency

Status: in progress, starting from merged H02 `7d56cf0`. H02 main-source
post-merge acceptance passed all eight browser/editor/PCM checks in
`artifacts/maiden/browser-20260909-045101/report.json` (main workspace).
All test-owned services were reaped. The separate Mosaic campaign is preserved.

Existing implementation: actual JACK stereo float PCM, bounded native and server
rings, authenticated browser requests, Web Audio resampling and explicit gaps.
H00 records the inspected reference commits and architecture/licensing decisions.
No reference implementation code is needed for this extension.

Missing capabilities and smallest changes:

- Audio reads currently wait for the action lock held during synchronous Lua
  callbacks. Give monitor lifetime/read operations their own lock, preserving
  ordered native controls and serializing stop/disconnect/session cleanup.
- A delayed request from a previous listening interval can affect the next one.
  Add an opt-in stream identity to the existing API; retain legacy requests for
  existing automation. Browser requests use the identity and ignore stale local
  asynchronous completions. Buffers remain bounded; gaps remain explicit.
- Input-to-browser-render latency is unmeasured. First measure the existing
  path with a generic supported engine and actual renderer samples, then tune
  buffering only against that baseline. Capture sample-rate, timing method and
  uncertainty; renderer output is distinct from physical speaker output.

Dependencies: existing Ubuntu20.04 WSL runtime candidate
`.runtime/engine-reload-01/installation.json`, Windows Chromium automation and
the existing browser controls. Maiden and Mosaic are not test dependencies.
No native engine replacement, secondary UI, default-install promotion or Docker
work belongs in this card.

Automated acceptance, before admission:

5. Run the focused package suite and bounded Codex Paranoia admission review
