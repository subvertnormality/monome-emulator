# C07 — Native clocks and replay

C07 passed on Ubuntu 20.04 WSL2. Final implementation revision: `a7cc140`, content
digest `47c452184ec78f1518509822db39e5ce8ca5920d92c1bbf541399246cb16c398`.
Verified manifests, measured values and artifact hashes are recorded in
[C07-evidence.json](C07-evidence.json).

Validation: 32 contracts with zero skips, three native clock tests, one native
blocked-file-I/O regression, eight fresh native scenarios (63 steps), and the
six-check actual Mosaic timing/transport package. The full contracts ran before
the native-only artifact I/O correction; all affected native packages ran after
it. Final Mosaic maximum onset/duration errors were 3.14/2.47 ms. Maximum snapshot
latency during scheduled waits was 28.0 ms. The final combined Lua/native/capture
cost probe measured 295.94 microseconds per message over 1,000 emissions; it is
not an isolated hardware benchmark or a guarantee of host timing under load.

The CLI replayed retained failed run `fe56ed95c72c40a08eefe94b8461308e` into new
passing run `4ef7ff8f49b24b17a42d9f8c09d3996e`. Old failure evidence stays failed.

The emulator retains official matron clock/run/sleep/sync/cancel, the native
internal clock, JACK frame time and metros. Literal MIDI markers verify callback
ordering, cancelled work, equal-deadline jobs, overlapping notes, tempo changes
and freed timers. A native transport restart invalidates existing beat anchors.
Beat waits and actions have bounded deadlines and retain native clock samples.

An explicit random seed controls the native Lua PRNG seed, including application
reseed requests; normal sessions retain upstream behaviour. Three fresh probe
processes must reproduce a standalone Lua 5.3 expected sequence. The ordinary
unseeded Mosaic boot remains a separate check. The runtime contains no Mosaic
musical logic or dependency.

The real Mosaic package sets tempo through the native parameter menu and builds
its four-step pattern through grid controls. It sets +25% swing and half-step
lengths using encoders, then checks literal pitches/velocities, 30/18-pulse swing
onsets and fractional note releases. Stop must drain counted notes and remain
silent; restart must reproduce the sequence. The native lattice's fractional
dispatch convention is documented separately from intended musical duration.
Both values are retained in the strict timing-report schema; tolerances cannot
absorb arbitrary rounding. No upstream Mosaic changes are used.

The original 128-frame dummy JACK profile accumulated phase error under xruns.
An isolated three-period probe measured frame time against monotonic time and
identified 1024 frames as the viable candidate. D17 records that host adjustment;
native time sources and central timing/interaction thresholds are unchanged.
The first attempted explicit long clock-source option was rejected by JACK
1.9.12; omitting it uses the already-selected system clock. Failed runs remain
retained rather than counted as passes. Ten-minute endurance remains C12 work.

Replay then caught a 13.8 ms fractional-release outlier (retained package
`fe56ed95c72c40a08eefe94b8461308e`). Investigation found synchronous framebuffer
writes inside the native event-reader lock: mounted-workspace p99 write latency
was 16.1 ms and maximum 38.0 ms. Writes now occur after releasing the lock and
unchanged frames are not rewritten. A real native regression holds a file write
blocked while four quarter-beat MIDI callbacks must still arrive. This establishes
and fixes the reader-stall mechanism without claiming complete causation of the
single historical outlier. No timing threshold was changed.

Future MIDI waits now serialize actions separately from the observation lock.
Two real 1.5-second waits preserve held input and heartbeats while snapshots stay
responsive. Invalid timestamps still fail explicitly with retained request/error
traces. R10 is resolved. R14 assigns Python's asynchronous Popen handoff warning
to C11's process lifecycle work; it is visible in current test logs.

Replay validates retained input/artifact hashes, then reruns the current source
in a fresh process. Failed and older-source cases can therefore be used during
development. Their old acceptance evidence is never made current or successful.
Ordinary recipes retain replay.json; registered procedural packages print their
origin and execute the current registered test entrypoint. The contract suite
checks failed-case replay and rejection of changed retained inputs.
