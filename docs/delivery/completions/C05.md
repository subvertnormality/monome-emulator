# C05 — Native MIDI and Mosaic port/scale controls

Passed on Ubuntu 20.04 WSL2: four native package checks, three verified native/API
scenario manifests, and 25 contracts with zero skips (72.282 seconds). The native
round trip captured 1189 emissions. Sources remain the official locked norns and
libmonome repositories; ten explicit native patches are now applied.

```sh
./dev/emu build
python3 tests/midi_native.py
./dev/emu test --suite contracts --require-all
./dev/emu run fixtures/scenarios/native-grid-level-conversion.json
./dev/emu run fixtures/scenarios/native-midi-stream.json
./dev/emu run fixtures/scenarios/mosaic-midi-init.json
# Verify each returned manifest with ./dev/emu verify-evidence <path>
```

The generic probe asserts actual discovered names for three ports, all 16 MIDI
channels, note-on/off, velocity-zero off, CC extremes, program changes, transport,
realtime, running status, SysEx and partial inputs across packet/chunk boundaries.
Scheduled input is not emitted before its requested backend monotonic time.
Missing ports, undefined statuses and past timestamps fail. Literal byte/port
oracles reject captured wrong-channel and omitted-release mutations, and the
independent sequence checker rejects a missing emission. A separate actual native
session reaches a deliberately tiny capture limit and fails with `midi_overflow`.

Actual Mosaic starts with the exact ten Sinfonion initialization program changes
followed by three port stop messages. Through grid, encoders and K3 confirmation,
the test selects a MIDI device, channel 16 and output 2. Injected C4 produces the
literal expected channel-16 note-on/off on output 2. Scale slot 1 then changes C
to C# and major to harmonic major during real playback; output 3 emits the expected
Sinfonion root/degree/mode/transposition values. The scale-page indicator remains
visible and stopping leaves no outstanding captured notes. Required malformed and
missing configuration fixtures fail before application startup with named errors.

Mosaic exposed two adapter issues during implementation: temporary native MIDI
name storage and stricter-than-upstream grid level validation. The first now uses
native device-owned strings. The second follows official norns signed storage and
libmonome four-bit packing (D15), proven with independent literal -4/31/260 and
relative-clamp examples. Mosaic itself is unchanged. P1 must review this corrected
boundary; earlier diagnostic failures are retained rather than counted as passes.

Evidence paths and digests: `C05-evidence.json`. Native packages retain source/app/
runtime identity, inputs, raw MIDI/frame/LED observations, logs and clean service
exits. The I/E manifests verify artifacts and current identities. `midi` snapshots
are a declared 4096-event tail; the complete native log, total count, source
sequence, timestamps and capture limit are retained separately. No dropped stream
can silently become successful evidence.

Changes: native patches 0009/0010, `src/devices/midi`, configurable session/CLI/
scenario ports, input timing, capture, JSON data-seed validation, probes and tests.
See `docs/architecture/midi-contract.md`. C06 owns edit/play/save/reload and P1;
C07/C12 own full timing and endurance. C05 is not full A14 recording/mapping or
M1 acceptance. No manual testing or physical hardware was used.
