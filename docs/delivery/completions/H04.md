# H04 optional Docker distribution

Status: in progress after H03 merge `996c67c`. Main-source browser/audio smoke
`artifacts/audio/latency-1788930271910/report.json` (main workspace) passed both
rates, 24 silence/onset checks, six lifecycle checks and independent native
cleanup. Main's concurrent state and two Mosaic active records were unchanged.

## Existing capability, gap and selected architecture

H00 records the exact inspected Winder and Schollz commits and licensing limits.
Their container/service topology is useful; no reference code is copied. We
already build pinned official norns/libmonome, own JACK/crone/sclang/matron,
provide browser controls/grid/MIDI, persistent datasets and optional PCM audio.
The missing capability is a container users can build and run with editable
host scripts and persistent data while retaining the same launcher/API.

Use an Ubuntu 20.04 Linux/amd64 base identified by digest first, matching the
working WSL userspace. Record and pin resolved build/package inputs. Build the
official sources through the existing locked fetch/build and optional audio
builder, not by copying host binaries or a community fork. Exclude fixture app
checkouts, host runtime caches, user data and credentials from the build context.
Retain dependency source/licence records. Native arm64 remains a separate target.

The smallest launcher extension provides an explicit fixed HTTP port and bind
address for container use. Normal WSL keeps loopback and an automatically chosen
port. Publish the container port on host loopback using the same port number;
preserve bearer/origin checks and the shared native input path. The container
entrypoint calls the existing session launcher, waits for its owned server,
handles termination and exports its actual session metadata. No second UI,
screen capture, simulated runtime or host-wide process killing is introduced.

Mount disposable/editable code at a stable declared code root and launcher-owned
data at a persistent path. Reuse H02's explicit dataset creation/reopening and
single-writer marker/lease; do not adopt arbitrary directories silently. Inspect
the native launcher for required namespace/shared-memory privileges, prove the
smallest configuration, and document it rather than granting broad privileges
without evidence. Desktop Pulse/physical devices are optional host integrations;
browser PCM is the first portable audio output route.

## Host dependencies and facts

The existing Windows Docker service was running, but its engine pipe was absent.
Starting the installed Docker Desktop in the background made its engine available:
Desktop 4.12.0, Engine/client 20.10.17, Linux/amd64 server on Windows/amd64.
The Ubuntu 20.04 Docker shim initially reported integration unavailable; Windows
Docker CLI can drive the engine without changing the WSL installation. No Docker
upgrade, global integration setting or unrelated container was changed. No macOS
host is available; this does not establish macOS or Apple Silicon support.

## Implementation refinements

Resolved Ubuntu's Linux/amd64 manifest to
`sha256:c664f8f86ed5a386b0a340d981b8f81714e21a8b9c73f658c4bea56aa179d54a`.
Docker20's manifest-inspection command rejects OCI media types; the registry API
provided the descriptor, and the existing engine successfully pulled that exact
digest. No Docker upgrade is needed. A disposable prerequisite container installed
the declared build/runtime dependencies successfully; all 496 resulting package
versions are locked in `scripts/container/packages.lock.json`. Rebuilds must
match that package inventory, including transitive dependencies.

Native launcher inspection finds ordinary subprocesses, socketpairs, private
temporary paths and a session-named JACK server; it does not require mount
namespace privileges. Start the image without extra capabilities or device
passthrough and measure any actual shared-memory requirement. Use a non-root
runtime user and preserve host ownership rather than recursively chowning mounts.

Prepare a build context from a committed Git bundle, not the worktree's `.git`
pointer or untracked host caches. The image checks out the actual emulator commit,
so existing source identity works without synthetic revisions or fallback hashes.
Container scripts and package lock live under `scripts/`, already covered by the
source digest. All official runtime sources are fetched/built inside the image.

The first image omits optional Maiden packaging: its extra WebSocket listener and
session-restart port mapping need their own container integration evidence.
Existing WSL Maiden remains available. Fixed HTTP ports cannot be combined with
Maiden restart in this first extension; reject that unsupported combination
explicitly at startup. This does not narrow the H04 baseline browser/grid/MIDI/
audio/data contract or replace H02's working default-port path.

A small container-owned marker and held lock identify a mounted data root and
point to the existing launcher's generated dataset. Restart reopens that exact
owned dataset. Refuse a nonempty unmarked root; retain H02's mapping/single-writer
checks. Never clear a mount or overwrite an arbitrary user's directory.
